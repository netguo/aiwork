AI Agent Infrastructure（Agent Infra）深度调研报告

调研日期：2026-08-13 调研范围：商业化市场产品 + 开源生态 + 企业本地建设 + 行业趋势 数据口径：GitHub star 数为 2026-08-13 实时查询近似值；市场数据来自公开报道，标注「待确认」处未能核实到一手来源。

一、执行摘要

  1. Agent Infra 已从"跑通 Demo"进入"可治理的生产组合件时代"。选型不再赌单一框架，而是沿 vLLM/SGLang → LiteLLM/Higress → LangGraph/OpenAI Agents SDK → Qdrant/Milvus → Langfuse → MCP/FastMCP 这条标准主线搭配微调。推理层与向量库层最成熟，编排层在 2025–2026 完成格局洗牌（Swarm 退役、AutoGen 迁仓、Google ADK 入场、Pydantic AI 崛起），低代码平台（Dify/LangFlow/n8n）进入 150K+ star 的高速增长期。

  2. 商业化市场呈"平台化/被大厂整合"趋势。可观测性是全球最拥挤赛道（Langfuse vs LangSmith 双强），网关进入整合期（Palo Alto 收购 Portkey、Helicone 并入 Mintlify、Langfuse 被 ClickHouse 收购），向量库被云厂商收编。新增价值向评估（eval）、治理、安全、MCP 管控等纵深环节迁移。国内呈"云巨头生态 + 垂直创业公司"二元结构，独立的观测/安全工具化机会显著。

  3. 企业落地瓶颈已从"模型能力"转移到"治理/评估/集成"等基础设施层。Gartner、信通院、麦肯锡三方独立得出同一结论：模型只占约 20%，剩下 80% 是工程。LangChain 调研显示 eval 采用率（52%）严重滞后于 observability（89%），是最大缺口；Forrester 数据显示无自动 eval 的 Agent 年回滚率 47% vs 全 eval 覆盖者 9%。

  4. MCP 已完成事实标准化，进入"幻灭谷底 + 企业硬化期"。SDK 月下载近亿次，归入 Linux Foundation 治理；「MCP is dead」之争本质是个人开发者效率叙事与企业治理叙事的错位。2026 下半年焦点是安全（OAuth 2.1 强制、MCP Gateway、Registry 治理）与互操作（A2A 协同）。

  5. 企业本地建设（私有化）已形成成熟分层架构范式：8 层架构 + 横切治理，开源组合成本可控，国产化（DeepSeek/Qwen/GLM + 昇腾等）链路初步贯通但软件栈兼容性是大坑。金融/政务/医疗"数据不出域"实践已验证，一体机在月 token 消耗过临界点后成本降至公有云 API 的 1/3–1/5。

二、概念与范围界定

Agent Infrastructure（Agent Infra） 指支撑 AI Agent 从开发、部署到运行、治理的一整套工程化基础设施，横跨多个层次：

层级 解决的核心问题
推理/模型服务层 模型部署、吞吐、KV Cache、量化
模型网关层 多模型接入、路由、降级、预算、成本控制
记忆与知识层 对话/长期记忆、向量检索、RAG、GraphRAG
工具与 MCP 层 企业系统对接、权限管控、工具注册治理
Agent 编排层 任务规划、图状态机、多 Agent 协作、HITL
可观测与评估层 trace、eval、Prompt 管理、灰度、回归
安全与合规层 Guardrails、认证授权、审计、数据不出域
应用/交互层 多入口接入、认证鉴权、限流路由

关键认知：LLM 只是依赖，系统才是产品。企业不能只套一个框架的原因——模型每季度更换、供应商每年更换、合规要求随时变化，单体硬编码"某模型+某向量库+单个 Prompt"会在任何一环变动时崩溃；且多租户配额、成本拆解、权限审计、GPU 调度、灰度发布等单框架均不解决。

3.3 模型 / LLM 网关

  • LiteLLM：开源（MIT）自托管网关事实标准，100+ 供应商统一 OpenAI 接口，虚拟 Key、团队预算、fallback、缓存。自托管免费，Cloud/Enterprise 另计。月 PyPI 下载 4.18 亿，商业化待解。
  • Portkey：企业级托管网关，语义缓存（实测降成本 30–50%）、50+ Guardrails、SOC2/HIPAA。2026 年被 Palo Alto Networks 收购，向"安全主导的企业 AI"演进。
  • OpenRouter：SaaS 模型聚合市场，400+ 模型一键调用，按 token 转售 + 5.5% 平台费。
  • Kong / Cloudflare / Azure AI Gateway：分别面向既有 API 管理栈插件化、边缘免费（缓存/限流/分析）、微软生态深度绑定。
  • 国内：中科闻歌·海汇 TokSea（2026.07 发布，统一接入+智能路由+预算/审计治理，"AI 国家队"）；Higress（阿里开源）国内生产落地多。

洞察：网关正在被安全/可观测大平台吸收（Palo Alto 收 Portkey、ClickHouse 收 Langfuse、Mintlify 收 Helicone），独立纯网关生存空间收窄。

4.2 生态全景洞察

  • 成熟度分层：推理层与向量库层最成熟，进入"性能与运维"竞争期；编排层 2025–2026 完成洗牌，收敛为 OpenAI Agents SDK（轻量标准）/ LangGraph（深度生产）/ Pydantic AI（类型安全新贵） 三强并立。
  • 衰减信号：MetaGPT、TGI、LoRAX、Portkey、rebuff 等早期明星项目在 2026 集中显现"明星税"——选型须以 2025–2026 活跃度为锚。
  • 标准收敛（三层）：OpenTelemetry（GenAI 语义约定）统一观测层；MCP 统一工具层；OpenAI 兼容 API 成为推理/网关/框架共同方言。跨厂商组合成本大幅下降。
  • 推荐参考组合（2026 主流）：
    • 生产组合：vLLM/SGLang → LiteLLM/Higress → LangGraph 或 OpenAI Agents SDK → Qdrant/Milvus + pgvector → Langfuse → MCP + FastMCP → Guardrails AI
    • 轻量替代：Ollama/llama.cpp → Chroma/LanceDB → Pydantic AI → Langfuse/Opik
    • 国内企业变体：Dify/RAGFlow + vLLM + Higress + Milvus + Langfuse

5.2 七个关键设计议题

  1. 模型接入与统一网关：OpenAI 兼容 API 屏蔽差异；按 Key/团队/用户预算上限（已有企业因成本叫停模型使用）；Fallback 需区分错误类型（5xx 可重试、429 读 Retry-After、参数/安全拒答不重试）；Token 级限流五维（用户/租户/模型/供应商/预算）先预扣后对账。
  2. 成本控制：五层缓存（精确缓存 FAQ 降调用 30–80% → 语义缓存（阈值≥0.95 防"同义反义"陷阱）→ 供应商 Prompt Cache（稳定系统提示放前缀，折扣 50–90%）→ 引擎 KV Cache → 结果片段缓存）；分级模型路由（70% 流量用小模型，综合成本降 40–60%；RouteLLM 报告降 85% 成本保留 95% 质量）。
  3. 多 Agent 编排选型：确定性流程用 workflow，复杂状态用图编排。LangGraph 生产成熟度最高（Uber/LinkedIn/Klarna 等 30+ 大厂案例，checkpoint 断点续跑）；CrewAI 适合快速原型；AutoGen 对话式易死锁需 max_turns 硬限制；商业平台适合低代码快速落地但深度定制受限。
  4. 记忆分层：会话记忆（Redis）→ 长期记忆（向量库+结构化库，带权限标签）→ 工作流状态（PostgreSQL 持久化，LangGraph checkpoint 保证重启不丢状态）。容量一上来就必须有淘汰策略。
  5. MCP 企业化：Gateway 模式集中管控（MxN 集成变 1 次）；OAuth 令牌端到端传播、用户上下文不替换（防权限提升）；scope 级操作治理；JSON Schema 校验；审计日志接 SIEM；高危操作（发发票/改合同/删数据）人工审批。金融实践：广发证券 MCP 工作台上线 110+ MCP 服务；度小满用 MCP/Skill/CLI/Codebox 扩展执行边界。
  6. 可观测与评估（AgentOps）："Trace is the truth"——Agent 是图执行，表面指标全绿也可能工具用错；eval 驱动开发（发布门禁=回归套件通过）、线上失败样本回填评测集、OpenTelemetry 统一 trace。指标分层：使用/质量/RAG（召回命中、引用正确）/Agent（工具成功率、越权拦截）/成本/性能/稳定性。
  7. 安全与合规：三件套——对接 LDAP/AD SSO、细粒度 RBAC（部门/角色/密级三维）、全链路审计。Agent 专属风险：Prompt 注入、token 跨服务器重放、工具抢占（squatting），用网关+PKCE+Resource Indicator 缓解。Guardrails 放网关层而非业务层。关键动作加 HITL 审批闸门。

5.4 国产化 / 信创与私有化考量

  • 模型：DeepSeek、Qwen3、GLM、Kimi K2 均成熟适配国产算力。选型经验：80% 政企场景 Qwen3-32B 是性价比天花板（INT4 量化单卡 32GB 可跑）；强推理用 DeepSeek 蒸馏系列；集团级上 Qwen3-235B/DeepSeek-V3 系 MoE。
  • 硬件：昇腾/海光/昆仑芯等已初步贯通"模型→推理框架→RAG→Agent"全链路，但 vLLM/SGLang 适配仍在完善——部署前必须做兼容性验证和性能压测，这是国产化最大的坑。
  • 合规三维：等保（基础门槛）+ 数据安全法（红线）+ 信创（硬性要求）；需完成数据分类分级、国密加密（SM4）、关闭遥测外报、模型备案。
  • 混合云与一体机：公有云适合试错与弹性波动；私有化/一体机适合长期高频生产——Agent 是 7×24 消耗 token，月用量过临界点后一体机单 token 成本降至公有云 API 的 1/3–1/5，且断网可用。典型架构：模型与 Agent 解耦，本地多模型通过网关热切换。

5.5 实施路径建议

  1. PoC（2–4 周）：选 1 个只读低风险工具 + 1 个 Agent，验证工具发现、身份令牌、可观测打通。
  2. 试点（2–3 月）：上 MCP Gateway、集中 OAuth 与限流，接 2–5 个工具，建立 trace 与离线评测集。
  3. 规模化（3–6 月）：接入企业身份、scope 级授权、成本预算、灰度发布，从单 Agent 到多 Agent 协同。
  4. 持续运营：eval 驱动迭代、失败样本回流、治理体系（AI 与人工边界、回滚机制）。

团队能力：需要"平台工程"（网关、评测、可观测）+ 业务融合（场景定义）双团队，而非仅算法工程师。度小满经验：让业务员工基于平台自建 Agent（反洗钱 Agent 由业务团队 1 人 1 周建成）。

七大常见坑：① 评估缺失就发布；② trace 不透明无法归因；③ 工具失控（无权限管控的 Function Call 直操生产系统）；④ 幻觉难治理（必须 RAG+GraphRAG 锚定企业知识）；⑤ 只买 GPU 忽略软件栈兼容性；⑥ 语义缓存全量开放（金融/法务风险高）；⑦ 多 Agent 对话死锁不设 max_turns。

六、行业趋势与权威观点

6.1 权威机构判断

  • Gartner（2026）：Agentic AI 正处于"期望膨胀高峰期"；仅 17% 组织已部署 Agent，但超 60% 计划两年内部署（被称为调研中最激进采用曲线）；治理、安全、FinOps for Agentic AI 首次独立上曲线；完全自主 Agent 尚未准备好用于大多数企业用例。预测 2027 年底超 40% agentic AI 项目将被取消（成本失控/价值不清/风控不足）；2028 年至少 15% 日常工作决策由 Agent 自主做出。
  • Gartner 中国网安 Hype Cycle（2026）：AI Gateway 被定义为"管理和保护与 AI 提供商连接"的安全治理平台（多模型路由、DLP、成本可视化、行为审计）；到 2028 年超 80% 中国企业将出现员工无管理的生成式 AI 使用。
  • 信通院（2026.06）：企业 AI 从"模型采购期"进入"系统改造期"；四大瓶颈为模型幻觉、数据孤岛、人机权责边界模糊、缺乏全流程安全审计；工程化分三层——Prompt 工程 / Context 工程 / Harness 工程。
  • Gartner 语义层（2026.05）：到 2027 年，语义化 AI-ready 数据的企业 Agent 准确率提升最高 80%、成本降低最高 60%。
  • 市场规模（口径差异巨大）：狭义"企业 Agent 基础设施"市场 2025 年 3.6 亿 → 2026 年 5.4 亿 → 2031 年 43.9 亿美元（CAGR 52%）；广义"Agentic AI 基础设施" 2025 年 244.8 亿 → 2032 年 1039.5 亿美元（CAGR 22.9%）。引用数字必须先明确口径。

6.2 技术趋势热点

  1. MCP 企业化治理：公共服务器 9400+（部分来源称 Q1 已超 1.7 万）；约 78% 企业 AI 团队已有 MCP-backed Agent 在生产（方向性数据）；RSA Conference 2026 上 MCP 安全成焦点，多数公共服务器被扫描出可利用风险、仅少数默认启用 OAuth——出现 mcp-scan 等专用扫描工具与 OAuth 2.1 强制要求。
  2. Agent 评估成为刚需：89% 组织已做可观测性但仅 52.4% 跑离线评估；Forrester 数据显示无自动 eval 的 Agent 年回滚率 47% vs 全 eval 覆盖者 9%。OpenAI Evals 平台将关闭转向代码内可编程评测；评估正在从"仪表盘仪式"变成 CI 发布门禁，以"端到端任务完成率、工具调用精确度、升级正确性、单任务成本"四指标代替原始准确率。
  3. 多 Agent vs 单 Agent 祛魅：Gartner 预测 2027 年 1/3 agentic AI 部署进入协作阶段；但社区共识"planner/executor/reviewer 架构增加的是故障点而非能力""只在问题真正需要时才加 Agent"。
  4. RAG 没死、在分层：Naive→Advanced→Modular→GraphRAG→Agentic RAG 逐代演进；混合检索（BM25+向量+结构化过滤）成为 2026 基线；Agentic RAG 让模型自主决定何时检索、检索几次。
  5. 成本治理从边缘走向中心：多模型路由（Mistral 约 $2/百万 token vs GPT-4o $5，组合路由省约 65%）、语义缓存（生产命中率 40–70%；AWS 实测降成本 86%、延迟 88%、准确率 91%+）、厂商 prompt caching（Anthropic cache_read 打 0.1 折）、小模型+编排成为生产标配。
  6. 持久化执行（durable execution）：Temporal D 轮 3 亿美元、估值 50 亿美元（380% YoY）——in-memory agent state 在生产中会破裂，durable execution 被视为生产架构方向。

6.3 社区讨论：共识与分歧

  • LangChain vs 自研：口碑极化（HN 2026-04 置顶帖"我们花了 6 个月把产品迁出 LangChain"800+ 评论）；但 LangGraph 因图状态机+检查点在金融/政务/工业强流程场景"无替代品"。共识：框架本身不重要，瓶颈是 prompt、工具设计与编排逻辑。
  • Agent 生产可用性：88% 试点不达生产（Anaconda/Forrester）；22% 部署 12 个月后负 ROI；麦肯锡称约 89% 企业级 AI 规模化失败归因于集成复杂度、质量不稳定、缺监控、所有权不清、领域数据不足——均非"模型不够聪明"。
  • MCP 前景之争：2026-03 Perplexity CTO 宣布弃用 MCP（工具定义消耗 72% 上下文）引爆"MCP is dead"；Scalekit 测算 MCP 比 CLI 多耗 4–32 倍 token；2026-04 爆出 MCP RCE 设计缺陷。但企业团队观点："要的是审计与治理"。MCP 与 A2A 互补而非竞争（A2A 解决 agent 间通信，MCP 解决 agent 连接工具，同归 Linux Foundation 治理）。
  • 企业采用现状：LangChain《State of Agent Engineering 2026》——57.3% 组织已有 Agent 在生产（10k+ 人企业达 67%）；客服（26.5%）与研究/数据分析（24.4%）是最常见用例；质量（32%）是第一障碍。Sinequa——84% 遇到"Agent Washing"、88% 因此降低对 AI 的整体信任；仅 24% 达到"真 Agent"标准。Digital Applied/Forrester——成功进入生产的 12% 具备共同画像：94% 有命名 owner、87% 每次变更跑自动 eval、74% 首 60–90 天 HITL 检查点、68% 采用 MCP、63% 以单任务成本为主指标。

七、选型决策框架

按企业类型选择路径：

场景 推荐路径 理由
已有云厂商深度绑定 云平台（百炼/方舟/千帆）+ 平台内置观测 运维成本最低、生态集成顺滑
需要私有化/数据不出域 vLLM + LiteLLM + LangGraph + Milvus/Qdrant + Langfuse + MCP Gateway 全链路可控、成本随用量下降、符合合规
业务团队低代码快速落地 Dify / RAGFlow + 私有化部署 中文生态成熟、插件丰富、可发布为 MCP 服务
单机/边缘/轻量 Ollama + Chroma/LanceDB + Pydantic AI 零运维、离线可用
强流程/高合规（金融政务工业） LangGraph + durable execution（Temporal）+ 深度 Guardrails + 全审计 状态可恢复、过程可审计

四个决策要点：

  1. 评估能力优先于框架选择——没有自动 eval 回归门禁，任何 Agent 都会在生产回滚（Forrester：47% vs 9%）。
  2. 网关是企业化的分水岭——统一模型接入、预算、审计、Guardrails 下沉网关是"个人项目"与"企业系统"的分界线。
  3. MCP 已不可回避，但必须走 Gateway + 治理模式——裸接公共 MCP server 在安全上是灾难。
  4. 先单 Agent 跑通，再谈多 Agent——社区共识：多 Agent 增加的是故障点而非能力，只在问题真正需要时才加。

八、结论与行动建议

  1. Agent Infra 的核心矛盾已从"模型能力"转向"工程化与治理"——评估、可观测、网关、MCP 管控、成本治理是 2026 最热的预算线，也是企业落地的真实瓶颈。
  2. 商业化市场：可观测/评估与 MCP 治理是新增量机会；网关与向量库正被大平台整合；国内独立工具化机会（观测、安全）显著。
  3. 开源组合已成熟到"按标准主线搭配"的程度——建议以 vLLM + LiteLLM/Higress + LangGraph + Qdrant/Milvus + Langfuse + MCP/FastMCP 为基线。
  4. 企业本地建设建议按四阶段路径（PoC→试点→规模化→持续运营），把评估体系与审计治理作为一等的 first-class 建设，而非事后补丁。
  5. 跟进重点：MCP 企业治理（Registry/Gateway/OAuth 2.1）、Agent 评估门禁、语义缓存与成本治理、A2A 互操作、国产算力软件栈适配。
