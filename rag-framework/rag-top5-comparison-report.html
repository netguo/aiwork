3. RAGFlow — 企业级 RAG 引擎

核心定位

专注于企业级文档问答的 RAG 引擎，深度融合 DeepDoc 文档解析与 Agent 能力，提供完整的端到端 RAG 解决方案。

关键词

DeepDoc 模板分块 混合检索 引用溯源 MCP 支持

架构特点

维度说明
文档解析自研 DeepDoc 引擎，支持 PDF/Word/Excel/PPT/图片等 20+ 格式，具备 OCR、表格识别、版面分析能力，尤其擅长复杂 PDF（论文、报表、合同）
分块策略支持按段落、按页面、按章节、按模板等多种分块方式，可自定义分块规则，支持手动标注和调整
检索方式向量检索 + BM25 关键词检索 + 重排序（Rerank），支持混合检索权重调节
向量库内置 Elasticsearch / Infinity（自研）；可选支持 ChromaDB、Faiss
LLM 支持OpenAI / Claude / 通义千问 / 智谱 / 月之暗面 / Ollama / 本地模型，通过 API Key 配置即可切换
部署方式Docker Compose 一键部署，支持 K8s，提供 SaaS 版本
Agent 能力内置 Agent 模块，支持可视化编排工作流（DAG），可定义多步检索-推理流程
引用溯源每个回答附带原文引用位置，支持点击跳转原文片段
MCP 支持✅ 原生支持 MCP 协议，可作为 MCP Server 暴露知识库检索能力

✅ 优势

  • 文档解析能力行业领先，复杂 PDF 处理效果极佳
  • 开箱即用，UI 完善且可视化操作
  • 引用溯源能力强，适合企业知识库场景
  • 支持 MCP 协议，与 Agent 生态集成友好
  • 社区活跃，Star 数最高
  • 支持多租户、权限管理，企业功能完善

⚠️ 注意事项

  • 整体架构较重，Docker Compose 部署依赖 ES + Redis + MinIO 等多个组件
  • Go + Python 混合技术栈，二次开发门槛略高
  • Issue/Fork 比偏高（20.2%），部分 Issue 响应较慢
  • 与 LangChain 集成主要通过 REST API，无原生 Python SDK 桥接
  • Agent 编排能力相比 LangGraph 较弱，更侧重 RAG 本身

4. LlamaIndex — 文档 Agent 与 OCR 平台

核心定位

以数据为中心的 LLM 应用框架，提供从数据摄入、索引到查询的完整工具链，强调文档 Agent 与多模态能力。

关键词

LlamaParse 300+ 集成 VectorStoreIndex Query Engine 多模态

架构特点

维度说明
文档解析LlamaParse 云端服务支持 130+ 文件格式（PDF/DOCX/PPTX/HTML/图片等），含表格、图表、公式识别；也支持本地解析器
分块策略SentenceSplitter / TokenTextSplitter / SemanticSplitter（基于嵌入的语义分块）/ HierarchicalNodeParser（层级分块）
检索方式向量检索 + 关键词检索 + 知识图谱检索 + 子问题查询 + 递归检索 + FLARE（前向主动检索）
向量库30+ 向量库集成：Chroma / Pinecone / Weaviate / Qdrant / Milvus / pgvector / Faiss 等
LLM 支持通过 llama_index.llms 模块统一抽象，支持 OpenAI / Anthropic / Google / Azure / Ollama / HuggingFace / Cohere 等 40+ LLM
部署方式Python pip 安装，轻量级；LlamaCloud 提供托管服务；支持 Docker 部署
Agent 能力内置 ReAct Agent / Function Agent / OpenAI Agent，支持多 Agent 协作
高级特性多文档 Agent、文档摘要索引、自动路由查询、多模态检索（图文混合）
MCP 支持✅ 通过 llama_index.tools.mcp 支持 MCP Client

✅ 优势

  • 生态最丰富的 RAG 框架，300+ 数据集成
  • LlamaParse 文档解析能力极强（但为云服务）
  • 与 LangChain 同为 Python 生态，互操作性好
  • API 设计优雅，开发者体验好
  • 支持高级检索模式（递归、子问题、FLARE）
  • 文档质量高，教程丰富

⚠️ 注意事项

  • LlamaParse 为云服务，涉及数据隐私和费用
  • 框架本身偏向 SDK 库，不含 UI 和部署方案
  • 与 LangChain 功能重叠较多，同时使用可能产生混乱
  • 版本迭代快，API 变动较频繁
  • 无内置向量库，需额外部署

5. LightRAG — 轻量级图增强 RAG

核心定位

港大 HKUDS 团队开发的学术级 RAG 框架，EMNLP 2025 论文，以"简单、快速"为核心理念，融合知识图谱与向量检索。

关键词

Graph + Vector 双层检索 EMNLP 2025 5 种查询模式

架构特点

维度说明
文档解析基于 Python 基础解析器，支持 TXT/MD/PDF/DOCX，轻量级方案
分块策略Tiktoken Token 分块，可配置 chunk_size 和 overlap
核心创新双层检索架构：Low-level（实体精确匹配）+ High-level（关系主题推理），自动判断使用哪层
检索方式5 种查询模式：naive（纯向量）/ local（局部子图）/ global（全局推理）/ hybrid（混合）/ mix（全量混合）
知识图谱自动从文档中抽取实体-关系三元组，构建知识图谱，结合向量索引进行联合检索
向量库NanoVectorDB（内置轻量级）/ PostgreSQL + pgvector / Milvus / ChromaDB / Faiss / Qdrant
LLM 支持OpenAI / Azure / Ollama / HuggingFace / 智谱 / 通义千问 / DeepSeek 等，通过配置文件切换
部署方式pip 安装，极轻量；提供 Web UI（基于 Gradio）；支持 Docker
MCP 支持✅ 原生支持 MCP Server 模式

✅ 优势

  • 图+向量双层检索，复杂推理问题表现优于纯向量 RAG
  • 极轻量，pip install 即可运行，NanoVectorDB 零依赖
  • 学术级设计，论文背书（EMNLP 2025），算法可信
  • 5 种查询模式灵活应对不同场景
  • 支持 MCP Server，Agent 集成友好
  • 社区活跃，Issue/Fork 比仅 4.3%，维护良好

⚠️ 注意事项

  • 创建于 2024-10，相对年轻，生产环境案例较少
  • 文档解析能力不如 RAGFlow / LlamaIndex
  • 无 UI 管理界面（仅 Gradio Demo），不适合非技术用户
  • 知识图谱构建依赖 LLM 抽取实体，Token 消耗较高
  • 无多租户、权限管理等企业级功能

6. GraphRAG — 微软图增强 RAG 系统

核心定位

微软开源的模块化 Graph-based RAG 系统，通过社区检测和层级摘要实现全局性推理能力，适用于大规模文档集的宏观分析。

关键词

Leiden 社区检测 层级摘要 DRIFT 搜索 Microsoft

架构特点

维度说明
文档解析基础文本解析，支持 TXT/MD/PDF/DOCX，通过 input adapter 扩展
分块策略Token-based 分块，可配置大小和重叠
核心创新Leiden 社区检测算法：自动将知识图谱中的实体聚类为社区，并为每个社区生成 AI 层级摘要，支持"全局性问题"回答
检索方式Local Search（实体子图）/ Global Search（社区摘要遍历）/ DRIFT Search（混合检索 + 图遍历，V3 新增）
知识图谱自动实体抽取 + 关系提取 → 图谱构建 → 社区检测 → 层级摘要，支持增量更新
向量库LanceDB（默认）/ Azure AI Search / Neo4j（图谱存储）
LLM 支持OpenAI / Azure OpenAI / Ollama / HuggingFace / 自定义 LLM 接口
部署方式pip 安装；支持 CLI 和 Python API；提供 Azure 部署模板
架构演进V3 Monorepo 架构：Python + Rust（核心性能模块），引入 FastAPI 服务层
MCP 支持✅ 通过 GraphRAG MCP Server 暴露检索能力

✅ 优势

  • 微软出品，工程质量和代码规范有保障
  • 社区检测 + 层级摘要，全局性问题回答能力突出
  • DRIFT 搜索融合图遍历与向量检索，检索精度高
  • Issue/Fork 比最低（1.7%），维护质量极高
  • V3 引入 Rust 核心模块，性能优秀
  • 学术与工业双重背书

⚠️ 注意事项

  • 索引构建成本极高（需大量 LLM 调用抽取实体+关系+摘要）
  • 更适合大规模文档集（100+ 文档），小数据集优势不明显
  • 文档解析能力较弱，复杂格式需预处理
  • 无 UI 管理界面，纯 CLI/API 使用
  • V3 架构变动较大，与 V2 API 不完全兼容
  • 与 LangChain 无原生集成，需自定义封装

7. Haystack — 生产级 AI 编排框架

核心定位

deepset 开发的 AI 编排框架，以 Pipeline 为核心抽象，模块化设计，强调生产环境可控性和可观测性。项目始于 2019 年，是 RAG 领域最成熟的开源框架之一。

关键词

Pipeline 架构 Context Engineering Hayhooks 生命周期钩子

架构特点

维度说明
文档解析Haystack 2.x 集成 Unstructured / Apache Tika / PDF 等多个转换器组件，支持 PDF/DOCX/PPTX/HTML/图片等
分块策略TokenTextSplitter / SentenceSplitter / 语义分块等，通过 Pipeline 组件灵活组合
核心架构Pipeline DAG 架构：每个处理步骤为独立 Component，通过 connect() 串联，支持条件分支、循环、并行
检索方式向量检索 / BM25 / 混合检索（Embedding + BM25）+ Reranker（Cohere / SentenceTransformers / HuggingFace TEI）
向量库Elasticsearch / OpenSearch / Pinecone / Weaviate / Qdrant / Chroma / pgvector / AstraDB 等 15+
LLM 支持OpenAI / Anthropic / Google / Cohere / HuggingFace / Ollama / Amazon Bedrock / Azure 等 20+
部署方式pip 安装；Hayhooks 组件将 Pipeline 部署为 REST API；支持 K8s / Docker
Context Engineering2.x 引入 Context Engineering 概念，显式控制检索结果如何注入 LLM 上下文
生命周期钩子组件级生命周期钩子（warm-up / dispose），支持资源预加载和清理
MCP 支持✅ 通过 haystack-mcp 适配器支持

✅ 优势

  • 最成熟的框架（2019年至今），生产环境验证充分
  • Pipeline DAG 架构清晰，可观测性和可调试性极佳
  • Hayhooks 一键部署 Pipeline 为 API 服务
  • 组件化设计，扩展性强，自定义组件开发简单
  • deepset 商业公司支持，长期维护有保障
  • Issue/Fork 比极低（3.9%），维护质量高

⚠️ 注意事项

  • Star 数最低（26K），社区热度不如 RAGFlow / LlamaIndex
  • 定位为 AI 编排框架而非纯 RAG，学习曲线略陡
  • 无内置 UI 管理界面（deepset Hub 为商业产品）
  • 与 LangChain 理念不同（Pipeline vs Chain），同时使用可能混乱
  • 知识图谱能力不如 LightRAG / GraphRAG

11. 与 LangChain 集成方案

团队已选定 LangChain + LangGraph 作为 Agent 基座。以下展示 5 个 RAG 框架与 LangChain 的集成路径：

框架 集成方式 集成复杂度 代码示例
RAGFlow REST API → LangChain Tool 中等 
from langchain.tools import Tool
import requests

def ragflow_search(query: str) -> str:
    resp = requests.post(
        "http://ragflow:9380/api/v1/retrieval",
        json={"question": query, "dataset_ids": ["ds_id"], "top_k": 10},
        headers={"Authorization": "Bearer YOUR_API_KEY"}
    )
    return resp.json()

ragflow_tool = Tool(
    name="RAGFlow_Search",
    description="搜索企业知识库",
    func=ragflow_search
)
# 在 LangGraph 中作为工具节点使用
LlamaIndex 原生 Python 互操作 低 
from llama_index.core import VectorStoreIndex
from langchain.tools import Tool

# LlamaIndex 构建索引
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()

# 包装为 LangChain Tool
def llama_search(query: str) -> str:
    return str(query_engine.query(query))

llama_tool = Tool(name="KB_Search", 
                  description="搜索知识库", func=llama_search)
LightRAG Python SDK 直接调用 低 
from lightrag import LightRAG, QueryParam
from langchain.tools import Tool

rag = LightRAG(working_dir="./rag_storage")

def lightrag_search(query: str) -> str:
    return rag.query(query, param=QueryParam(mode="hybrid"))

lightrag_tool = Tool(name="Graph_Search",
                     description="图谱增强检索", func=lightrag_search)
GraphRAG 自定义封装 / MCP 较高 
# 方案1: 通过 MCP Server 集成
from langchain.tools import Tool
import subprocess

def graphrag_search(query: str) -> str:
    result = subprocess.run(
        ["graphrag", "query", "--method", "global", 
         "--query", query],
        capture_output=True, text=True
    )
    return result.stdout

# 方案2: 使用 GraphRAG MCP Server
graphrag_tool = Tool(name="GraphRAG_Search",
                     description="全局图谱检索", func=graphrag_search)
Haystack Hayhooks REST API 中等 
from langchain.tools import Tool
import requests

def haystack_search(query: str) -> str:
    resp = requests.post(
        "http://hayhooks:1416/v1/pipelines/rag_pipeline/run",
        json={"inputs": {"query": query}}
    )
    return resp.json()["result"]

haystack_tool = Tool(name="Haystack_Search",
                     description="Pipeline检索", func=haystack_search)

集成策略建议

策略方案适用场景
方案 A：单框架直接集成选择 1 个 RAG 框架作为 LangChain Tool快速验证、小规模团队
方案 B：分层组合RAGFlow（生产引擎） + LightRAG（图谱增强）双 Tool推荐 兼顾文档解析与图谱推理
方案 C：MCP 统一协议所有 RAG 框架作为 MCP Server，LangGraph 通过 MCP Client 统一调用长期演进、多知识源

12. 选型建议

🎯 最终推荐：分层组合策略

主力：RAGFlow（企业知识库） + 补充：LightRAG（图谱增强推理）

结合团队已选 LangChain + LangGraph 基座，建议采用双框架分层组合策略，而非单一框架。

生产层 RAGFlow 企业知识库主力引擎 • DeepDoc 文档解析能力最强，处理复杂 PDF（合同/报表/论文）
• 完善的 UI + 引用溯源 + 多租户权限，开箱即用
• 86K Star 社区最活跃，Apache-2.0 许可证商用友好
• 原生 MCP 支持，通过 REST API 集成为 LangChain Tool
• 内置 Agent DAG 可作为 LangGraph 的补充
增强层 LightRAG 图谱增强推理补充 • 图+向量双层检索，复杂关联推理问题表现突出
• 极轻量（pip install + NanoVectorDB），部署零负担
• 5 种查询模式灵活应对不同检索场景
• EMNLP 2025 论文背书，算法可信
• 原生 MCP Server，集成简单
• 与 RAGFlow 互补：RAGFlow 强在解析+精确检索，LightRAG 强在关系推理

为什么不选其他框架？

框架未选为主力的原因
LlamaIndex 与 LangChain 功能重叠严重，同时使用两个框架会导致架构混乱；LlamaParse 为云服务，数据隐私风险；无 UI 管理界面。但其检索模式设计优秀，可在需要时作为 SDK 层参考。
GraphRAG 索引构建成本极高（大量 LLM 调用），不适合频繁更新场景；更适合超大规模文档集（1000+文档）的全局分析；与 LangChain 无原生集成；V3 API 变动大。如未来有大规模文档分析需求可引入。
Haystack Pipeline 架构理念与 LangChain Chain 不同，同时使用增加认知负担；无知识图谱能力；社区热度较低。但其 Pipeline 可观测性和 Hayhooks 部署模式值得借鉴。
