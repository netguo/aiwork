综述：数字机器人全景

0.1 什么是数字机器人

数字机器人（Digital Robot / Digital Worker / Digital Labor）指以软件形态模拟人类工作行为的自动化实体。按"行为方式"可分为软件类与硬件类两大类：

大类 形态 代表 与本次报告关系
软件类·流程执行型 模拟人操作屏幕/API 完成重复流程 RPA（UiPath、实在智能） ✅ 本报告第 3 章
软件类·协作认知型 驻留协作工具、有记忆、以独立身份主动工作 AI Coworker（Claude Tag、Glean） ✅ 本报告第 1 章
软件类·业务编排型 跨系统编排流程、节点内 AI 决策、人工审批 Agentic 业务自动化（n8n、Workato、Dify） ✅ 本报告第 2 章
软件类·形象交互型 拟人形象+语音/表情/动作 数字人/虚拟人（硅基智能、魔珐） 未纳入本次范围
软件类·语音交互型 电话/呼叫中心机器人 IVA/IVR 客服机器人 未纳入本次范围
硬件类·通用/专用形态 物理机器人 人形机器人、服务机器人、机械臂 未纳入本次范围

本次报告聚焦软件类三个核心领域——它们共同构成企业"软件数字劳动力"的完整拼图：

0.2 三领域的本质差异（一句话定位）

领域 一句话 回答的核心问题 输入 输出 关键资产
AI Coworker 住在协作工具里的"数字同事" 谁来做（组织成员） 对话/频道上下文 协作成果（消息/文档/任务） 组织记忆、身份
Agentic 业务自动化 跨系统业务流程的"智能编排" 流程怎么做（治理框架） 事件/触发/数据 完成的状态/结果 工作流、审批、集成
RPA 数字员工 模拟人操作的"流程机器人" 具体动作怎么执行 确定的任务指令 确定的操作结果 选择器、确定性执行

一个形象比喻：如果把企业工作比作一场手术——Agentic 业务自动化是手术流程（术前评估→方案→执行→复核，有审批闸门），RPA 是主刀手的双手（对每台设备的精确操作），AI Coworker 则是病房里的主治医生（长期了解病人、跨天跟进、主动查房）。三者解决不同层面，互为补充而非替代。

0.3 综述核心发现

  1. 三领域正在收敛为"同一层"：2026 年的清晰趋势是 RPA 厂商向上加"AI 大脑"（Agentic RPA）、Agentic 平台向下补 UI 执行与审批（n8n/UiPath 双向渗透）、Coworker 向"执行+流程"延伸。三方都认识到：真正成熟的生产形态是"确定性编排 + 受控 Agent 决策 + 人工闸门"的组合。
  2. 品类定义权之争在"编排层"：RPA（UiPath Maestro）、Agentic 平台（Workato Orchestrator）、通用引擎（Temporal）、云厂商（Agent 365/Agentforce）都在抢"谁是企业自动化的编排中枢"。
  3. 三领域风险同源：凭证管理、审计缺失、权限越界是三个领域共同的三大风险；部署速度已快于防护能力（2026 安全事故：Claude Cowork 沙箱逃逸、Cursor 删库、欧洲银行机器人被劫持）。
  4. 采用现实：企业并非"用 A 替换 B"，而是混合部署——RPA 管结构化高吞吐段（可靠性 99.5%+）、Agent 管文档理解/异常路由/决策（92-97%）、人工管高风险审批。McKinsey 显示仅 23% 组织实现单职能规模化。
  5. 市场口径差异巨大：狭义 Agent 软件市场约 $10-12B（CAGR 44-46%）、RPA 存量市场 $14-35B（口径不一）、AI 自动化总市场 2026 约 $169B（GVR）。跨报告对比必须看口径。

0.4 综述：怎么选（任务性质决定技术）

三个领域的选型可归纳为 "不确定性 × 后果"二维决策矩阵：

                    后果高（强审计/高风险）
                          │
         RPA 数字员工      │   Agent 编排 + 人工闸门
         （对账/监管报送） │   （Agentic 业务自动化核心形态）
    ──────────────────────┼─────────────────────
         确定性工作流      │   Agent + 审批升级
         （低成本直接跑）  │   （人机协同，Coworker 参与）
                    后果低（低成本/试错）
        确定性低（多变）──────────────── 确定性高（固定）
  • 低不确定 + 高后果 → RPA（确定性执行、可审计）
  • 高不确定 + 低后果 → Agentic 自动化（Agent 节点自由处理）
  • 高不确定 + 高后果 → Agent 提议 + 确定性闸门执行（审批链）
  • 需要组织记忆与跨天协作 → AI Coworker 补充

六问法则（快速判断）：① 流程每次完全相同？→RPA ② 日均千次低毛利？→RPA ③ 低频需判断？→Agent ④ UI 频繁变更？→Agent ⑤ 真非结构化？→Agent ⑥ 高并发重判断？→混合。

第 1 章 AI Coworker（AI 数字同事）

本章来自 2026-08-13 独立报告《ai-coworker-深度调研报告》，此处为核心内容整合。

1.1 执行摘要

  • 品类定义：长期驻留、有组织记忆、以独立身份行动、可主动（ambient）工作的团队级 Agent——住在 Slack/飞书/Teams 里的"数字同事"。2026 年已从概念进入产品化与早期生产部署。
  • 市场格局：三梯队——① 平台巨头（Microsoft Agent 365、Google Gemini Enterprise、Salesforce Agentforce、钉钉"悟空"、飞书 Aily）；② 独立 Work AI 新贵（Glean 估值 $7.2B、Coworker.ai）；③ 开源/自托管（Centaur、Khoj/Pipali）与嵌入式创业公司（Viktor $75M A 轮、Superpal、Coworked）。
  • 技术共识：四层记忆 + 频道级作用域 + Agent 自有身份 + 凭证边界注入（绝不进模型内存）+ 步骤级持久化 + tool-call 级审计 + MCP 统一工具出口。
  • 核心风险：记忆越界（57–71% 的 Agent 存在跨用户记忆泄漏）、凭证泄漏、幻觉污染组织记忆；行业部署速度已快于防护能力。
  • 判断：对企业的唯一稳健路径是先治理后上量——凭证、记忆、审计三件套先行。

1.2 品类定义：四个架构原语

原语 旧模型（Chatbot/Copilot） Coworker 模型
记忆 会话级，断连即失 频道级持久存储，跨天累积隐性知识
身份 借用提问者权限 独立组织身份（服务账号），权限随"频道"而非随"人"
行为 被动等 @ Ambient 主动监控、跟进、触发
凭证 用户 token 进提示词上下文 网络边界注入，模型/沙箱永不接触原始密钥

微软 Nadella 的产业级概括：Agent 应被视同员工——唯一身份 + 隔离沙箱 + 安全策略 + 审计机制。

1.4 技术架构要点

  • 四层记忆：工作记忆（Redis/checkpointer）→ 情景记忆（事件日志）→ 语义记忆（向量库）→ 程序记忆（技能/流程）。生产系统必须管理生命周期：编码→检索→整合→驱逐。
  • 频道级记忆：每私有频道独立身份独立记忆（"法律频道知识不出现在工程频道"）；Git 化六原则：作用域界定、归公司所有、版本化、可审查、可审计、可移植。
  • 凭证三层防线（"agent 永不持密钥"）：① 网络边界注入（Credential Proxy/Iron Proxy，出口默认拒绝）；② Just-in-Time 短效令牌（OAuth token exchange/WIF/SPIFFE）；③ 每通道独立凭证、独立审计归因。
  • 持久状态：服务无状态 + 状态落 Postgres + 步骤级 checkpoint，崩溃从断点恢复；Multiplayer 多人共享会话。
  • ambient 机制：静默观察→轻量建议→自主执行（需双人审批开通）三级防打扰模型；高风险写操作前置审批 + 全局紧急停机按钮。
  • 安全：PII 写入前脱敏、会话物理隔离、记忆投毒（跨会话持久注入）视为最高威胁、输出带 provenance 引用。
  • 协议：MCP=agent↔︎工具（私有）；A2A=agent↔︎agent（公网发现）。A2A 不解决身份认证——身份边界仍由组织 IAM + Credential Proxy 负责。

1.5 开源自建

推荐开源组合（七层）：推理 vLLM + Qwen3/DeepSeek ｜ 网关 LiteLLM ｜ 记忆 Qdrant + Postgres + Redis ｜ 编排 LangGraph/CrewAI ｜ 工具网关 自建 MCP server + Iron Proxy ｜ 可观测 OpenTelemetry ｜ UI 入口 Slack/钉钉 bot。

实施路径：PoC（2-4 周，单渠道、3-5 只读工具、会话记忆）→ 试点（1-2 月，加写操作带审批、跨天记忆、基础审计）→ 生产（2-3 月+，凭证间接模式、checkpoint 跨天任务、全链路审计、成本治理）。

1.6 关键风险

坑 数据/现象 缓解
记忆权限越界 57–71% Agent 存在跨用户记忆泄漏 per-user namespace + 召回 principal 校验 + 向量物理分区
凭证泄漏 密钥残留内存/日志/trace Secrets Broker 仅返回脱敏结果
幻觉污染组织记忆 错误推断被反复引用 记忆写路径 provenance + 审核 + TTL
Agent 失控 OWASP ASI03 权限继承 委派 scope-down；支付/删除强制 HITL

2026 安全事故（均多源核实）：Claude Cowork 沙箱逃逸（CVE-2026-46331，影响约 50 万 macOS 用户）、Meta Rogue AI 越权（Sev 1）、Cursor 删库（生产库 9 秒被删）。

第 2 章 Agentic 业务自动化

本章来自 2026-08-14 新调研（3 路并行：商业化市场 / 技术架构 / 开源生态与趋势）。

2.1 执行摘要

  • 品类定义：把 AI Agent 能力注入跨系统业务流程编排的平台——流程骨架确定，节点内 AI 决策。介于"纯协作型 Coworker"与"纯 UI 执行型 RPA"之间，通常具备：可视化/低代码编排、事件触发、跨系统连接器、Agent 节点、HITL 审批、状态持久化。
  • 市场格局：第一梯队为 n8n（2.5B）、Temporal（5B）、Zapier/Workato 等存量巨头；第二梯队为 Lindy、Relevance、Activepieces 等创业公司；第三梯队为国内钉钉/飞书/字节 Coze、开源 Dify、大厂云（百炼/ADP/千帆）。
  • 技术路线二分：Anthropic 定义的「预定义路径 workflow」vs「模型自主决策 agent」是买方选型第一刀；控制力（审计/审批/回滚）成为企业采购核心决策项，而非单纯智能。
  • 采用现状：生产里真正跑的是"确定性编排 + 受控 Agent 节点"（bounded autonomy），全自动无人值守 Agent 罕见；Gartner 2026 CIO 调查仅 17% 组织已部署 AI Agent。
  • 核心风险：出错责任不清、审批流被绕过（影子 IT）、token 成本失控、Gartner 预测 40% agentic 项目 2027 底前被取消。
  • 判断：Agentic 业务自动化将从"独立品类"演变为企业软件的基础设施层；编排引擎（Temporal）+ 低代码平台（n8n/Dify）+ 集成层 MCP 是推荐技术栈。

2.2 编排范式谱系（关键概念）

范式 决策来源 成本 适用
确定性工作流（DAG/状态机） 人预定义 发票处理约 $0.001/次 高吞吐、强合规流水线
半确定性/混合编排（2026 主流） 骨架确定，节点内 LLM 做分支 中 大多数生产系统
完全 Agentic 编排 模型动态选工具、递归子代理 约 $0.05/次（50 倍） 高不确定、低后果场景

关键洞察：能画出流程图就用确定性工作流；流程图依赖 LLM 运行时发现才确定，才需要 Agent。纯 Agent 链有"复合可靠性问题"——每步 99% 可靠，10 步流程仅 90% 成功，且退化随链长加速。

混合模式典型结构：确定性层（输入校验/预处理）→ Agent 层（推理/路由/草拟）→ 确定性层（合规检查/格式化/投递）。

2.4 技术架构要点

状态持久化与断点续跑（生产可用的分水岭）

  • Temporal durable execution：每步 checkpoint、崩溃从断点恢复；workflow 代码必须确定性（crash 后 replay），所有副作用（LLM 调用/工具/写库）封装为 Activity 带幂等键；OpenAI Codex 在 Temporal 上生产运行，Temporal Cloud 已处理 9.1 万亿次动作执行。
  • LangGraph checkpointer（PostgresSaver/RedisSaver）实现"时间旅行"回放。

人工审批闸门 HITL（三种模式）

  1. 不可逆动作前审批：草拟→暂停→approve/reject→继续或回退。
  2. 阈值触发审批：置信度/金额超阈值才升级人工。
  3. 异步审计：动作执行后另开复核任务。

基础设施要求：持久挂起（暂停数分钟到数天）、完成 API、超时升级策略、审计日志、审批者上下文（输入+AI 建议+置信度+策略依据）、权限分离（提出者≠审批者）。

Agent 节点设计（Dify 范式）

  • 节点像普通节点一样有标准输入输出，对上下游透明（"引擎与控制系统分离"）。
  • 执行三阶段：初始化 → 迭代循环（构造 prompt→调 LLM→是否需工具→执行→更新上下文，达迭代上限即停）→ 最终响应。
  • 结构化输出（JSON Schema/function calling）保证下游可消费。
  • 防"无限循环 Agent"：max_iterations（Dify 默认 5）、loop budget cap、turn 限制、成本上限。

集成层与 MCP

  • MCP 把工具集成从"每模型每工具的胶水代码"变为"写一次 MCP server，任何兼容 Agent 可用"。
  • 大规模工具三模式：progressive discovery（延迟注入工具定义）、programmatic tool calling、catalog→inspect→execute。
  • n8n 已支持把自身工作流作为 MCP Server 暴露给外部 AI 系统——工作流本身变成工具。

安全与合规

  • 凭证管理：平台代管 + OAuth + 运行时注入（区别于 RPA 凭证库、Coworker Credential Proxy 的"完全代持"）。
  • EU AI Act：透明度义务 2026-08-02 已生效；高风险义务（Annex III）延至 2027-12；招聘/信贷/医疗/关键基础设施的自主 Agent 很可能被定为高风险；罚款上限 €35M 或全球营收 7%。
  • 审计：EU AI Act Article 12 要求防篡改日志（Merkle tree / SHA-256 hash chain）。

  • 社区：HN/Reddit 主流声音是"能 demo 不能生产"；国内社区聚焦就业焦虑与 ROI 兑现。

2.9 推荐技术栈与实施

  • 起步场景："四特征"——高频/重复/跨系统/需判断（报销审核、开票、对账、客服分流优先）。
  • 路径：先确定性工作流 + 受控 Agent 节点，再渐进提升自治度；高影响动作设强制人工检查点；治理前置（Agent 注册表、权限最小化、token 预算、审计追踪在试点期建立）。

3.1 执行摘要

  • 品类定义：通过模拟人在 GUI 上的键鼠操作或 API 调用，自动完成重复业务流程的"流程机器人"；平台由设计器 Studio、机器人 Robot、控制台 Orchestrator 三件套组成。2026 年正经历从"确定性脚本执行"向"Agentic 流程自动化"的范式迁移。
  • 市场现实：UiPath FY2026 营收 $16.11 亿（+13%）增速放缓；Gartner 口径 2025 全球 RPA 市场约 $39 亿（+9.1%）；中国市场 2026 预计破 70 亿元（IDC）。纯规则 RPA 作为独立品类在萎缩，增量来自 AI 增强型与 Agentic 平台。
  • 技术共识：选择器→计算机视觉（CV/ISSUT）是抗 UI 变化的关键升级；确立"AI 负责智能决策 + RPA 负责精确执行"双引擎模式。
  • 核心争论："RPA 已死" vs "RPA 不可替代"——真实答案是进化：RPA 降格为自动化技术栈的"执行层"（失败率 <1% vs Agent 5-20%）。
  • 判断：不向 Agent 转型的 RPA 厂商将在 2028 年前面临严重市场挤压；企业应走 keep-route-retire 策略，混合架构优先。

3.3 技术架构要点

UI 自动化底层技术

  • 选择器四级成熟度：属性定位→结构定位（DOM/CSS/XPath）→图像/OCR→坐标。致命弱点：依赖应用"后门"标识，前端 CI/CD 每周发布时代"脚本上线即过期"——30-50% RPA 项目失败主因。
  • 计算机视觉：UiPath AI CV（目标检测+OCR 双路）、实在智能 ISSUT（智能屏幕语义理解，"目之所及皆可操作"）、Automation Anywhere Citrix Plugin（ICA 协议级交互）。CV 比选择器更抗 UI 变化。
  • Citrix/远程桌面：无 DOM 无控件句柄，只能图像识别+锚点+坐标。

运行模式

  • Attended（有人值守）：员工工作站前台，人触发、可暂停等待人工输入。
  • Unattended（无人值守）：Orchestrator 定时/事件触发，24/7 后台运行；直通处理率（STP）80-95%，异常自动路由人工队列。

Agentic RPA 融合

  • NL2Workflow（一句话生成流程）、对话式 RPA（自然语言→拆解→执行→校验→异常自愈）。
  • Computer Use 现实对比：RPA 同任务 5-10 秒、失败率 <1%；Agent 30 秒-数分钟、$0.1-1/任务、失败率 5-20%。结论：融合而非替代——RPA 处理 80% 结构化主路径，Agent 负责语义判断、异常与多变界面。
  • IDP 四层架构：采集预处理→分类→信息提取（规则/ML/LayoutLM/LLM）→人工反馈闭环。传统 OCR 85% 准确率→叠加 LLM 校验 98.7%。
  • 自愈：UiPath Healing Agent（JIT 分析→级联恢复：关弹窗→调选择器→智能等待），支持同义语义识别。
  • 流程挖掘→RPA 发现闭环：DAOG 框架（Discover→Automate→Orchestrate→Govern）。

RPA vs AI Agent 技术边界（六问分配法则）

  • RPA 不可替代：无 API 老旧系统（COBOL/AS400/Citrix）、强确定性可审计（KYC/AML/财务稽核）、高吞吐低成本（日均万级）。
  • 被 Agent 蚕食：语义网页抓取、邮件分类路由、多模板文档提取、长尾低频。
  • 六问：流程每次完全相同→RPA；日均千次低毛利→RPA；低频需判断→Agent；UI 频繁变更→Agent；真非结构化→Agent；高并发重判断→混合。

3.6 趋势、风险与信创

  • "RPA 已死"争论：支持方（API 普及、AI Agent ROI 8:1 vs 2:1）；反对方（确定性/可审计不可替代、Forrester 预测 <15% 企业 2026 启用 Agent 功能）。2026 社区共识：进化而非替代。
  • 凭证管理是头号风险：23% 权限提升事件涉及被盗机器人凭证（Gartner）；68% 运行无人值守机器人的组织缺乏机器人级安全监控，近一半明文存储凭证；欧洲银行对账机器人被劫持 11 周、外泄 84 万条账户数据（行业博客，中等可靠度）。
  • 信创硬门槛：2027 年国产化替代 deadline；三大障碍——Linux 系无法运行依赖 Windows API 的 RPA、国产 OS 控件树不同、指令集差异需重新编译；AI 视觉方案（ISSUT/UI-TARS）天然绕过控件树依赖，是信创场景独特优势。
  • 岗位替代：重复性文职替代概率超 80%（经济参考报）；RPA 开发者岗位自身被冲击（需求缩减 10-15%，转向"智能自动化工程师"）。

4.4 综合选型决策框架

  1. 系统是否有 API？ 无 API 遗留系统 → RPA（含 CV）是唯一方案。
  2. 流程是否高频且规则明确？ 是 → RPA 优先；否/多变 → Agentic 编排。
  3. 是否需要组织记忆与跨天协作？ 是 → 引入 AI Coworker 层。
  4. 是否需要强确定性与审计？ 监管报送/KYC/AML → RPA 执行 + 审批闸门。
  5. 信创是否硬约束？ 2027 deadline → 优先国产厂商或 AI 视觉路线。
  6. 治理是否就绪？ 凭证代理、记忆作用域、tool-call 级审计三件套未就绪前，不要规模化上量。
