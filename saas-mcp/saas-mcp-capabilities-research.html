SaaS 公司 MCP 能力调研报告

调研日期：2026-08-10 范围：国内外 SaaS · MCP 能力 + 未来趋势 知识库

核心结论：MCP 已从 2024 年的开源协议演变为 2026 年 SaaS AI 接入的事实标准。国外 SaaS 偏"直发远程 server + OAuth"，国内大厂偏"平台市场聚合 + 生态卡位"。不接入 MCP = 站在 Agent 分发之外。

一、背景：MCP 是什么

Model Context Protocol (MCP) 是 Anthropic 于 2024 年 11 月开源的协议，被称为 "AI 时代的 USB-C 接口"。通过 client-server 架构（JSON-RPC 2.0）让任意 AI 模型与外部工具/数据源标准化对接，把 "M 模型 × N 工具 = M×N 自定义集成" 的复杂度降到 "M+N"。

三个核心原语

  • Tools：可执行函数（如创建联系人、发送消息、跑 SQL）
  • Resources：可读数据（如客户记录、文件、仪表盘）
  • Prompts：预置工作流模板

关键里程碑

SaaS 公司接入 MCP 的战略动因：① 抢占 Agent 时代分发入口；② 避免被 AI 生态边缘化；③ 降低自建 AI 集成的工程成本；④ 把既有 API 资产以"Agent 可调用"形态二次变现。

六、未来 SaaS 在 MCP 层面的 7 大趋势

趋势 1：本地 stdio → 远程 OAuth 托管（已成主流）

2026 年新发布的官方 server 几乎全部采用 HTTP/SSE + OAuth 2.1 远程托管，用户"输入 URL 即用"。Streamable HTTP 取代 stdio，让 MCP server 能挂在云负载均衡和 API 网关后。本地 stdio 仍保留于 IDE 工具/文件系统等"本地信任"场景。

趋势 2：大厂竞相做 MCP 市场（国内特有且最激烈）

阿里云百炼、腾讯云知识引擎 + MCP Hub、百度千帆 + MCP Store、字节扣子、TraeWork 等抢"AI 流量入口"。对标智能手机"应用商店引爆生态"的剧本，MCP 市场可能成为 AI 时代的分发钥匙。

趋势 3：从"只读"到"读写+执行"端到端闭环

能力从"让 AI 看到数据"升级为"让 AI 完成业务"。Stripe 完整支付闭环、支付宝收款闭环、Cloudflare 部署闭环、Zapier 8000 应用编排是典型。下一阶段会向高价值写操作（退款、合同签署、资金转移）延伸，伴随 human-in-the-loop 审批。

趋势 4：安全与治理从"可选"变"必选"

MCP 2026 路线图三大焦点：OAuth 2.1 默认化、审计日志标准化、网关/代理模式。NIST AI Agent Standards Initiative 预计 2026 Q4 发布互操作 profile；EU AI Act 2026-08 全面执行，高风险 AI 系统的 MCP 调用需满足网络安全/日志/人类监督要求。独立扫描显示多数公开 MCP server 存在路径穿越/命令注入/SSRF 风险——治理层是下一阶段的核心战场。

趋势 5：MCP + A2A 双协议栈成为企业编排底座

MCP 管 agent-to-tool，A2A (Agent-to-Agent) 管 agent-to-agent 委托。A2A 已在 150+ 组织生产使用。两者共同构成 2027 年多厂商企业 Agent 编排的骨干。SaaS 不仅要暴露 MCP，还要考虑被多 Agent 协作调用时的状态/会话/委托语义。

趋势 6：SaaS 产品形态从"Dashboard+API"转向"Agent 调用即服务"

Cloudflare 明确称"首批 MCP-first 企业有先发优势"。Forbes 通过 MCP 把内容运营开发依赖去掉，年省 18000 工时、落地页转化率翻倍。这意味着 SaaS 的第一入口正在从人机交互界面（Web UI）让位给 Agent 调用接口（MCP tools）。产品设计要同时服务"人"和"Agent"两类消费者——API 描述要语义化、错误要结构化（RFC 7807）、响应要强类型。

趋势 7：垂直行业与遗留系统的 MCP 化是下一片蓝海

目前饱和：CRM、DevOps、云数据库、协作通信。部分覆盖：现代 ERP（Dynamics 365）、医疗（FHIR）、电商（Shopify）。严重缺口：遗留 SAP ERP、大型机、受监管金融基础设施。SaaS 公司若能把垂直行业深度能力（如合同审查、临床试验、合规审计、供应链对账）封装为 MCP server，将在 Agent 时代获得行业级卡位。

七、给 SaaS 公司的行动建议

  1. 现在就出 MCP server：不接入 = 站在 Agent 分发之外。先覆盖读+搜索，再逐步开放写与执行。
  2. 远程优先 + OAuth 2.1：远程托管 + OAuth + PKCE 是 2026 默认，降低用户接入摩擦。
  3. 按数据域拆分 server：参照 Pinterest 多 domain-specific server 模式，避免单体 server。
  4. 审计日志从第一天起：记录 who/which model/what tool/what args/what result，满足 EU AI Act 与企业采购要求。
  5. 细粒度 scope：把现有 RBAC 映射为 read:* / write:* scope，敏感操作用 Rich Authorization Requests 做一次性授权。
  6. 机器可读的信任清单：在 README/manifest 中声明"读什么/写什么/副作用/失败模式"——H2 可能会被规范正式化。
  7. 国内 SaaS 优先上大厂市场：借百炼/千帆/扣子/MCP Hub 分发，再建自建入口；同时关注 NIST 互操作 profile，避免被单一市场绑定。
  8. 垂直行业是蓝海：把行业深度能力（法务、财税、医疗、制造）封装为 MCP，抢行业级卡位。

八、垂直领域中小 SaaS 的 MCP 发展

前文聚焦头部 SaaS 与大厂，本节专门看垂直领域的中小 SaaS——它们既不像 Notion/GitHub 有足够工程团队自建远程 server，也不像阿里腾讯有平台市场背书，但恰恰是 MCP 生态中"最被低估也最活跃"的一层。

SaaSpocalypse 模式：当 Claude Cowork 等通用 Agent 能直接完成"文本搬运型"工作流，核心价值仅是工作流编排（非专有数据）的中小 SaaS 首当其冲被替代——法律 CLM、文档审查、提案生成、HR 绩效评估是第一批。聪明的应对不是对抗，而是把自己变成带"专有数据 + 审计留痕"的 MCP server：通用 Agent 能调你的工具，但离不开你的行业数据与合规记录。

8.2 国内垂直中小 SaaS 的 MCP 进展

国内垂直中小 SaaS 已大面积接入 MCP，主要通过三条路径：① 大厂平台市场（百炼/千帆/扣子/MCP Hub）；② WorkBuddy 等客户端连接器生态；③ 自建官方远程 MCP。代表性案例：

8.3 垂直中小 SaaS 的三条路径选择

  1. 上大厂市场（最快、流量大）：接入百炼/千帆/扣子/MCP Hub，借平台分发，但受平台规则约束、数据可能过平台。
  2. 自建官方远程 MCP（可控、体现数据资产价值）：像智慧芽/企查查那样自托管远程 MCP + API Key/OAuth，直接面向 Claude/Cursor，但需自维护工程与鉴权。
  3. 第三方 MCP 托管（折中、省工程）：通过 Vinkius/Smithery/Pipedream 等托管平台把已有 API 包装成 MCP，适合没有专职 MCP 工程团队的小厂，但治理层依赖第三方。

8.4 机遇与挑战

机遇：垂直行业是 MCP 生态最大蓝海（遗留 SAP ERP、医疗 FHIR、受监管金融仍严重缺口）；垂直 SaaS 手握专有行业数据 + 行业 know-how，这是通用 Agent 无法替代的护城河；按量计费/按任务计费的新模式让中小 SaaS 不再依赖账号订阅。

挑战：① 工程能力不足——多数中小 SaaS 没有专职 MCP 团队；② 数据合规与审计要求高（医疗/金融/法律）；③ "SaaSpocalypse" 风险——纯工作流编排型 SaaS 若不绑定专有数据会被通用 Agent 直接替代；④ 平台依赖——上大厂市场可能失去直连用户。

九、核心结论

MCP 已从 2024 年的开源协议演变为 2026 年 SaaS AI 接入的事实标准。

  • 国外：SaaS 偏"直发远程 server + OAuth"，治理与审计跟进，企业级硬化是当前阶段焦点。
  • 国内：大厂偏"平台市场聚合 + 生态卡位"，SaaS 借平台分发，支付/地图/企业数据等强数据型能力率先 MCP 化。
  • 未来 18 个月：远程托管 + OAuth 2.1 + 审计网关成为默认；MCP + A2A 双协议栈构成企业 Agent 编排骨架；垂直行业与遗留系统的 MCP 化是最大蓝海；SaaS 产品形态从"Dashboard + API"加速转向"Agent 调用即服务"。

对 SaaS 公司而言，MCP 不是"是否要接"的问题，而是"以什么粒度、什么治理、什么路径接"的问题。
