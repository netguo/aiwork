引言：从"单人"到"多人"的协作演进

我们与 AI 协作的方式正在从一种"单人"体验演变为"多人"体验——人类和 Agent 作为一个团队共同实现共享目标。本文将分享这种新工作方式的实际案例。

过去，使用 AI 意味着一个人面对一个聊天窗口。随着 AI 处理复杂、长时间运行任务（如编码、研究和财务分析）的能力不断增强，出现了许多新的使用方式——从终端和 IDE 到电子表格和演示文稿——但工作本质上仍然是"单人"体验：一个人与一个 Agent 协作完成个人任务。

随着 Claude Tag 等工具的发布，这种情况正在改变。现在，人类和 Agent 可以在同一个工作空间中协作，为团队共享的目标服务。工作现在更像一场多人游戏——团队中的人类制定策略，Claude 执行工作。

这涉及一些新的工作方式。在 Anthropic，过去几个月我们一直在测试使人-Agent 团队成功所需的技术。在本文中，我们将解释什么是"多人 Agent"，以及我们从中获得的经验教训。

图 1：AI 协作模式从"单人对单 Agent"向"人-Agent 团队"的演进

什么是"多人 Agent"？

"多人 Agent"是我们用来指代同时与多个不同人类协作的 AI 模型的术语。与常规 Agent 类似，它们有自己的记忆和技能。但在其他方面有很大不同——它们拥有自己的凭证，并且存在于工作发生的地方。在 Anthropic，那就是 Slack 等团队协作工具内部。

图 2：人类-Agent 团队在 Slack 中共同分析数据集的示例

要让 Agent 有效地参与团队频道，它们需要特定的能力：

  • 持久记忆——这样它们可以记住目标并据此调整执行方向
  • 不绑定人类的凭证——这样它们可以在安全、可预测的护栏内运行
  • 持续广泛的信息访问权限——这样它们可以学习组织的运作方式并采取行动以服务团队目标

这些能力构成了 Agent 在多人类团队中有效参与所需的技术基础。然而，使人-Agent 团队成功需要的远不止这些：团队还需要特定的工作方式和共享规范。

1公开工作并给予 Agent 广泛上下文

Anthropic 的团队主动且开放地共享信息。当 Agent 在团队中时，这一点尤为重要，因为 Agent 的理解完全建立在团队可搜索的文本之上：Slack、代码、文档和会议记录。私人消息、走廊谈话和受限文档无法为 Agent 提供上下文。

对于 Agent 来说，如果没有被写下来且可访问，它就不存在。

我们不是逐个文档或逐个 Slack 频道地决定哪些信息应对 Agent 可用，而是使用适用于整个 Slack 工作空间以及会议记录和文档库的明确定义的安全边界。在安全边界内，上下文流向每位队友——无论是人类还是 AI。

这不仅增加了 Agent 和人类可获取的信息量，还减少了关于什么可以与谁共享的混淆。人类和 Agent 都难以驾驭逐项共享的软边界：这个频道应该是公开还是私密的？我能把这个文档分享给那个人吗？这个 Agent 被允许看到那个对话吗？少量清晰的、工作空间级别的边界消除了日常工作中的决策疲劳。

图 3：逐项共享的混乱 vs 安全边界模型的清晰

高透明度的回报

高度透明是有回报的。例如：

  • 能读取团队会议决策的 Agent 不会建议已被降低优先级的任务或项目
  • 有权访问超出自身团队范围产品规格的 Agent 可以推荐已为他人成功的模式
  • 由于 Agent 阅读大量文本的速度远快于人类，它们经常浮现人类可能遗漏的相关工作

我们严重依赖 Agent 来在繁忙、快速变化的行业中保持信息灵通和协调一致。

📌 在 Anthropic，公开工作的具体做法：
  • 在公司层面选择少数安全边界，创建与之匹配的工作空间和文档共享设置
  • 将新通信频道默认设为组织内公开，确保决策每次都记录在频道、文档和会议记录中
  • 撰写工件和会议记录时确保 Agent 能找到它们，因为 Agent 现在是团队文档的主要消费者
  • 确保 AI 获得完成工作所需的正确工具和信息

默认信息内部公开可能需要文化转变。但是，有上下文和没有上下文的人-Agent 团队之间的差异太明显，不容忽视。

当然，某些交互是敏感的，需要在单个人类和 AI 之间保持私密。对于这些情况，使用 Claude Tag 可以向 @Claude 发送直接消息，或者使用现有的 Claude.ai 和 Claude Cowork 应用程序。这些工具通过您的个人 MCP 连接器让 Claude 访问私人信息，同时确保对话和分享给 Agent 的内容保持私密。

2每个人类和 Agent 都有明确定义的角色和合适的工具

人-Agent 团队共享一份花名册、一套工件和一个工作空间。Agent 拥有自己的凭证、技能和工具访问权限。不同的 Agent 也承担不同的角色：例如，一个可能负责项目的数据分析，另一个持有并执行设计标准，第三个运行研究综合。

当项目启动时，人类与 Agent 聊天以确定分配哪些角色，以及人类和 Agent 将如何协作。

一旦人类和 Agent 的职责明确，一个 Agent 可能会启动其他 Agent，以确保特定任务由具有正确记忆和适当访问权限的 Agent 处理。重要的是，它们需要访问完成任务所需的所有工具：处理数据分析的 Agent 可能需要访问 BigQuery，执行 QA 的 Agent 可能需要访问 Playwright MCP。

图 4：一个典型的人-Agent 团队花名册，每个人类和 Agent 都有清晰的角色定义

清晰的角色和职责为人-Agent 团队的成功奠定基础。人类通常在 Agent 工作的相同线程中工作，但他们持有只有人类才能持有的角色。这确保一切协调一致，且人类判断应用于最重要的决策。没有清晰的角色，人们最终会在旁边运行个人 AI 舰队，重复工作并割裂团队的上下文。指标跟踪是一个常见案例：多人 Agent 可以一次性完成工作并让所有人看到相同的数字。

Claude Agent 分担代码库的日常维护工作——分类反馈、规划、编写代码、审查变更和报告状态。每个 Agent 拥有明确的任务，按自己的计划工作；人类设定目标并审查产出。

📌 在 Anthropic，明确定义角色的具体做法：
  • 达成一致的任务集：团队的人类和 Agent 就谁做什么达成一致
  • 在相同共享线程中工作：人类和 Agent 在同一线程中协作，任何人都可以从其他人中断的地方继续
  • 拥有正确的工具访问：人类和 Agent 都拥有完成各自工作所需的正确工具
  • 描述 Agent 的角色和范围：明确每个 Agent 负责什么、不负责什么

工程团队创建花名册的实践

Anthropic 的一个工程团队开始创建花名册来明确人类和 Agent 角色，因为这使推动工作变得更容易且更具体。早期见效的做法包括：

  • 特定角色帮助人类轻松追踪任务责任所在——无论是在个人任务还是整个团队职责集中
  • 编写技能文件来定义特定 Agent 的角色——使专业化变得容易，并允许公司各处的人快速启动同类型的其他 Agent
  • 当项目变得更复杂时添加新 Agent 聚焦新领域——例如，他们添加了一个发布管理 Agent 来处理新软件发布

这些方法让人类对人-Agent 团队的心理模型随着 Agent 数量增长而扩展。

3设定北极星目标，让 Agent 更主动

虽然 Anthropic 的一些 Agent 只是完成分配的任务，但最重要的 Agent 会主动建议新项目和工作流。这通常发生在已经给予 Agent 丰富上下文和清晰角色的团队中，再添加一个指南：北极星。

北极星是雄心勃勃、影响广泛的目标，帮助团队决定哪些任务和工作流是正确的。在 Anthropic，人类总是设定北极星，将其扎根于业务使命和目标中。

图 5：北极星目标引导 Agent 主动建议新工作流

一旦北极星以书面形式清晰表达，人类就与团队中的 Agent 分享。然后，重要的是，人类选择哪些 Agent 应该主动建议新工作流来帮助实现这一长期目标。（不太可能团队中的每个 Agent 都具备主动成功建议工作所需的前提技能和信任。）

示例

一个内部工具团队的北极星是"让产品上手更有帮助"，看到一个 Agent 主动推荐了上手流程错误消息的文案修订。这些更改在接下来的一周可衡量地提高了上手成功率。

📌 在 Anthropic，设定北极星的具体做法：
  • 人类讨论、辩论并记录人-Agent 团队的雄心勃勃的北极星目标——扎根于公司使命和业务目标
  • 与团队中的 Agent 分享北极星，并明确命名哪些 Agent 可以主动推荐新工作流
  • 保护日历上的高保真人类时间，会议现在聚焦于最重要的工作

清晰的北极星为 Agent 提供了一致的工作方向和主动支持团队工作的有意义机会。

4随时间逐步建立信任

Anthropic 的团队根据 Agent 展示的可靠性按比例授予自主权，然后有意识地扩展。工程师已成功派遣团队中的 Agent 独立处理了 500 个 bug 修复，但事情最初肯定不是这样。

图 6：信任渐进模型——从手动审查到完全自主的四个阶段

当新人类同事加入团队时，需要时间来评估他们的能力并发展强健的工作惯例。通常需要多个反馈周期来外化所有关于如何最好完成任务的隐性信息。对于 Agent 也是如此。用户需要尝试给 Agent 许多不同任务，以便学习：

  • Agent 的能力是什么
  • 如何清晰描述目标
  • 需要什么技能文件
  • 哪些提示最能引发期望行为

还需要随着模型变化和改进重新测试任务。提示可能需要重新措辞，曾经有用的护栏可能会限制更智能的模型追求更有创造性的解决方案。

工作验证

我们发现的值得注意的是，最好的长期运行 Agent 有许多不同方式在人类查看之前验证自己的工作。代码有测试（当然），但大多数其他工作也可以被验证——例如，技术文档可以有应用于它们的评分标准和风格指南。当人类设定标准并确保分配给 Agent 的所有工作都可以被审查时，质量保持高水平，不会偏离原始意图。

"Doer-Verifier" Agent 架构：给一个 Agent 做任务的工作，另一个 Agent 检查第一个 Agent 的工作。这种模式让对抗性审查长时间运行，通常值得 token 消耗。

图 7：Doer-Verifier 架构——一个 Agent 执行，另一个独立验证，形成闭环

📌 在 Anthropic，随时间建立信任的具体做法：
  • 在开始时手动审查 Agent 工作——审查质量、提供反馈，并设计任务验证检查清单
  • 告诉 Agent 使用"验证者"Agent 来检查其工作作为任务的一部分
  • 在循环中建立反思——要求 Agent 审查自己的失误，使工作随时间改进
  • 追踪每个 Agent 在哪些类型任务上赢得了自主权，并在重复成功后按任务类型扩展范围

实践案例：工程领导者的积压工作处理

一位 Anthropic 的工程领导者接手了一个有大量积压工作的新团队。为了处理它，他邀请了几个人类和几个 Agent 来帮助他整理积压并优先处理最重要的内容。

第一组 Agent：分类与评分

  • 阅读积压中的所有项目
  • 弄清楚是否有人在处理这些项目
  • 为任何无人认领的项目分配复杂度评分

第二组 Agent：代码变更

  • 从列表中读取，筛选到中低复杂度项目
  • 创建代码变更

在开始时，人类审查 Agent 做出的每个决策，并标记任何需要人类输入的。然后人类教 Agent 直接向人类浮现这些决策，确保有艰难权衡的决策总是有人类参与。

每周报告与持续改进

领导者和他的团队每周要求 Agent 编制一份周报，包括"教训和失误"，以便 Agent 跟踪错误并避免未来再次发生。随着时间推移，领导者能够给 Agent 越来越复杂的代码更改，并花更少时间指导 Agent 的日常任务。

Agent 独立后的沟通优化

一旦 Agent 更加独立，领导者教练它们将人类注意力视为稀缺资源：

  • 批量问题以便一次性回答
  • 重复关键上下文以让人快速上手
  • 限制每个人类一次看到多少内容

帮助 Agent 良好沟通确保它们保持有用和高效。一些人团队中有专门角色的 Agent，唯一职责是决定如何批量化和只提升最重要的通信给人类团队成员。其他人设定护栏围绕 Agent 每天应该做多少工作，以便人类能够有意义地参与工作。这样的护栏确保：

  • 人类保持对他们重要的技能
  • 需要人类审查的项目数量保持可持续

需要问的问题

在为人-Agent 团队奠定基础时，请考虑以下问题：

🔑 团队自检清单

  1. 信息可访问性：Agent 和人类需要的所有信息和访问权限是否都公开且可广泛搜索？
  2. 角色清晰度：你能写下团队花名册（人类和 Agent），并说出每个成员负责什么吗？
  3. 工具适配：团队中每个人类和 Agent 是否都有执行工作所需的正确工具访问权限？
  4. 质量验证：你是否有评分标准或测试供人类和 Agent 验证关键工作产品？
  5. 方向一致：你的团队是否有每个人都可以参考的清晰北极星？

前进方向

这些模式都不新——至少对人类来说不新。强有力的北极星、清晰的角色、强健的文档、共享的质量标准以及从错误中学习的空间，是我们几十年来已知的健康团队习惯。Agent 只是让不跳过这些基础变得更加重要。

从 Agent 中获得最多的团队，是那些最有意识地应用这些基本原理的团队。
