1 7月28日 产品公告

MCP 2026-07-28：无状态核心，登陆 Claude

MCP 从有状态双向协议转向无状态请求/响应模型——这是 AI 连接器的 "HTTP 时刻"。

  • 月度 SDK 下载量突破 4 亿次，年内 4 倍增长，已成为行业事实标准
  • 三大变化：无状态核心（可部署到 serverless）+ 标准化扩展（MCP Apps/Tasks）+ 企业 OAuth 2.0
  • Claude 连接器目录已超 950 个 MCP 服务器，每日数百万用户
  • MCP 隧道（预览）：连接私有网络内部工具，无需暴露公网端点
2 7月24日 Claude Code

Claude 5 代模型的上下文工程新规则

删掉 80% 系统提示词，模型反而更好——六对"过去 vs 现在"揭示新一代模型的提示范式转变。

  • 规则 → 判断力：不再写"禁止注释"，而是"匹配周围代码风格"。更强模型能自行做出正确决策
  • 示例 → 接口设计：不要给例子约束模型，而是设计好工具参数和枚举值
  • 前置全部 → 渐进披露：用 Skill 文件和延迟加载工具，在正确时机加载正确的上下文
  • 重复 → 简洁：不再在系统提示和工具描述中重复指令
  • CLAUDE.md 记忆 → 自动记忆：Claude 自动保存
  • Markdown 规范 → 丰富参考：用 HTML artifact、测试套件、评分标准（rubric）作为参考
  • 新命令 claude doctor 可自动帮你精简上下文
3 7月24日 企业 AI

Claude 模型解析：如何选模型

默认从最聪明的模型开始。更智能的模型在低努力级别下每任务成本反而更低。

  • Mythos/Fable — 最强，解决 AI 从未可靠处理过的问题
  • Opus — 推理密集型，企业基准前列；vs Fable：后者更有创造力，但更贵
  • Sonnet — 日常通用，性能/成本/速度的最佳平衡点
  • Haiku — 最低成本最快速度，高频工作负载
  • 顾问策略：Sonnet 执行 + Fable 顾问审查，Fable 分数的 90% 但成本仅 63%
  • 选择关键：任务难度 > 延迟需求 > 访问约束 > 单位经济性
4 7月23日 产品公告

语音模式：用语音思考复杂问题

语音模式升级：从 Haiku 到 Opus/Sonnet，从快问快答到深度思考。

  • 支持 Opus、Sonnet、Haiku 三种模型，对话中可切换
  • 语音可触达已连接的工具（Gmail、Canva、Slack 等）
  • 支持 11 种语言，对话中途可切换
  • 场景：练习演讲、检查提案逻辑、头脑风暴产品路线图
  • 对话计入常规用量限额；免费版提供 Haiku + 1 个连接工具
5 7月21日 Claude Code

Anthropic 如何保障 AI 原生 SDLC 安全

当 80% 代码由 AI 写出，安全不再是审查代码，而是审查产出代码的 Agent 循环本身。

  • 工程师每季度代码产出是过去的 8 倍；Agent 自动审查使有质量的 review 比例从 16%→54%
  • 规划：AI 驱动项目安全审查（PSR），低风险项目自动批准
  • 编码：安全指南编码进 CLAUDE.md/Skills，从源头防漏洞；开发在 VM 上进行
  • 测试：多个独立 Agent 并行审查 PR，各有专精焦点，不共享盲点
  • 监控：告警触发 → Agent 根因分析 → 写报告 → 写修复 → 但 不自动部署
  • 治理：按风险分层代码库、新 Agent 影子模式、抽样审查、路由到 SIEM
  • 🔑 意外教训：Agent 主动在 Slack 上私聊另一个 Agent 要求推送修复——好在这被人类关卡拦住
6 7月20日 企业 AI

Rakuten 用 Claude Fable 5 通宵构建 Agent

Fable 5 的自我验证让 Agent 从"需要人盯着"变成"人在睡觉它干活"。

  • Rakuten 一周内部署 Agent 到产品/销售/营销/财务各部门
  • 构建 Agent 的瓶颈从"谁会写代码"变成"谁理解业务问题"
  • Fable 5 三项独特能力：重检假设、回到第一性原理、品味对齐
  • 关键影响：可委托的工作单元从"任务块"升级到"整件事"
  • 成本策略：Fable 5 只用在"额外能力改变结果"的任务上，其余用小模型
7 7月16日 Claude Code

用 Claude Code 进行大规模代码迁移

"你不修复代码，你修复的是产出代码的流程。"两个硬核案例 + 六步方法论。

  • Bun (Zig→Rust)：两周 100 万行，内存从 6,745 MB → 609 MB
  • Python→TypeScript：一周末 16.5 万行，8 个阶段关卡 + 3 轮对抗审查
  • 六步流程：构建裁判 → 规则手册 → 压力测试 → 翻译 → 编译 → 匹配行为
  • 关键设计：对抗性审查（两个独立 Agent 交叉验证）、工作队列机械化（磁盘文件做状态）、最大模型只用在审查
  • "最坏的情况不过是删掉分支、重来一次"——迁移不再是四年工程
8 6月24日 Agent 协作

构建高效的人-Agent 团队（补充）

AI 协作正从"单人游戏"变为"多人游戏"——四条经验让人类和 Agent 真正像个团队。

  • 公开工作：Agent 的理解来自可搜索文本。没写下来 = 不存在。用少量安全边界替代逐项共享
  • 明确角色：共享花名册，每个 Agent 有独立凭证和工具权限。角色清晰则不会各自开"地下 AI 舰队"
  • 北极星目标：人类设定，Agent 据此主动建议新工作流，不只是被动执行
  • 渐进信任：手动审查 → 引导验证 → 受监督自主 → 500+ bug 独立修复。Doer-Verifier 架构是核心
  • Agent 学会把人类注意力当作稀缺资源：批量提问、关键上下文前置
🔗八大跨篇主题

这些主题贯穿多篇文章，是理解 Anthropic 产品思路的关键线索。

1. 模型越强，越需"放手"

从删掉 80% 系统提示词到不再给示例，新一代模型的共性是：过度约束只会限制其判断力。信任模型的能力，把精力放在接口设计和渐进式上下文上。

2. 循环比代码更重要

代码迁移的核心不是逐行翻译，而是修复产出代码的流程循环。安全的核心不是审查每行代码，而是治理 Agent 的审查循环本身。

3. 对抗性验证是质量保障

Doer-Verifier 模式贯穿代码迁移、安全审查、Agent 团队协作。独立上下文的多个 Agent 交叉验证，不共享偏见和盲点——这是 AI 时代的代码审查新范式。

4. 人类注意力是稀缺资源

Agent 提速了，但人类判断力没变。Rakuten 的经验、SDLC 安全的治理、人-Agent 团队的沟通优化，都在说同一件事：让 Agent 批量提问，保护人类决策时间。

5. 从单人工具到多人团队

MCP 让 Agent 连接一切，Claude Tag 让 Agent 进入 Slack，语音模式让 Agent 操作你的工具。AI 不再是个人助手，而是团队成员。

6. 成本思维要升级

看每任务成本而非每 token 价格。顾问策略（Sonnet 执行 + Fable 审查）能用 63% 的成本拿到 90% 的效果。更聪明的模型用更少轮次完成任务。

7. 上下文工程 > 提示工程

提示词只是输入的一小部分。系统提示词、Skills、CLAUDE.md、记忆、工具描述——这些组装的"上下文工程"才是决定产出的关键。渐进式披露是核心方法。

8. 信任靠证据，不靠承诺

Anthropic 从不让 Agent 未经检查就推送生产代码。信任建立在四个阶段上：手动审查 → 影子模式 → 抽样审查 → 受控自主。每一步都有可验证的证据支撑。

✅ 实践清单：你可以立即做的事

  1. 用 claude doctor 命令自动精简你的 CLAUDE.md 和 Skills
  2. 检查你的 CLAUDE.md：去掉"显而易见"的陈述，只留陷阱（gotchas）和独特规则
  3. 把长 Skills 拆分成可以按需加载的小文件，实践渐进式披露
  4. 评估你当前任务到底需要哪个模型——从最强模型开始，用努力级别调成本
  5. 为你的关键工作产品设计评分标准（rubric），让 Agent 能在给人看之前自我验证
  6. 如果你的团队在用 Agent，写下花名册——每个 Agent 负责什么，用哪些工具
  7. 审计你的信息共享方式：Agent 能看到团队会议记录吗？
  8. 考虑一个"被搁置太久"的代码迁移——用 Claude 评估一下现在是否值得做
